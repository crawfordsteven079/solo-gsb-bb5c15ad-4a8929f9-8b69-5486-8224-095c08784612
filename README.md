# Call Board · 舞台监督排演与现场执行系统

供舞台监督（Stage Manager）在**排演阶段编排提示**、在**现场执行 GO / Skip** 的 Web 应用。
数据通过 PostgreSQL 关系型数据库保存在本地（Docker 命名卷），无需任何外部服务。

## 功能一览

- **场次与提示编排**
  - 录入场次；按序排列 **灯光 (LX) / 音效 (SQ) / 布景 (SC)** 提示（可上下移动调整顺序）。
  - 为每个提示设置一个或多个**前置提示**。
  - 发布前自动校验：**缺失引用、自引用、循环依赖、空执行单、重复编号**，错误逐条列出。
- **不可变执行单（版本快照）**
  - 校验通过后发布版本（v1、v2…）。发布内容（提示、顺序、前置、说明）被完整复制为快照，之后不再改变。
  - 排演中继续修改草稿**不影响**任何已发布版本。
- **现场执行台**
  - 每场演出从**某一已发布版本**启动**独立记录**，与之后的草稿改动、新版本完全隔离。
  - 四种状态实时展示：**待执行 / 已触发 / 已跳过 / 受阻（前置未触发）**，可按状态筛选，进行中每 3 秒自动刷新。
  - 仅当**全部前置均已触发**时提示才可「触发 GO」；受阻项的触发按钮不出现（后端同样强制拦截）。
  - **跳过必须填写原因**；受阻项可以跳过（用于设备故障等例外），原因会留存。
  - 每条结果记录**操作人与时间**；已结束的演出不能再写入。
- **并发安全**
  - 同一场次/提示的并发操作以数据库行锁 + 唯一约束串行化：**同一提示只保留第一次有效结果**；
    冲突请求收到 `409`，并在错误信息中告知该提示当前状态、首次操作人与时间。
- **历史回看**
  - 任意已结束/进行中的演出都锚定其启动时的版本，可随时按当时执行单回看；版本页为只读快照。
- **明确的错误提示**：无已发布版本、非法依赖、前置不满足、重复操作、演出已结束等均返回中文错误。

## 一键启动（Docker Compose）

前置：已安装 Docker 与 Docker Compose 插件（`docker compose version` 可用）。

```bash
# 1.（可选）自定义端口 / 数据库账号
cp .env.example .env
#   编辑 .env，主要是 WEB_PORT（默认 8080）

# 2. 构建并启动
docker compose up -d --build

# 3. 查看日志确认就绪
docker compose logs -f app
```

启动后在浏览器打开：

> **http://localhost:8080**

- 首次启动数据库会自动建表并写入示例数据（一名默认监督 + 一个已发布 v1 的示例场次）。
- 停止：`docker compose down`
- 停止并**清空全部本地数据**：`docker compose down -v`（会删除 `pgdata` 卷）

## 配置项（环境变量 / `.env`）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `WEB_PORT` | `8080` | 浏览器访问的宿主机端口（容器内固定 3000） |
| `PGUSER` | `callboard` | 数据库用户名 |
| `PGPASSWORD` | `callboard` | 数据库密码 |
| `PGDATABASE` | `callboard` | 数据库名 |
| `PGPORT_HOST` | `127.0.0.1:55432` | 数据库映射到宿主机的地址（仅绑定回环；不需要可忽略） |

数据库文件存储在 Docker 命名卷 `pgdata`（容器内 `/var/lib/postgresql/data`），数据保存在本机。
初始化脚本位于 `db/init/01_schema.sql`，**仅在数据卷首次创建时执行**；修改它后需要 `docker compose down -v` 重新初始化。

## 使用流程

1. 右上角选择或新建**操作人**（所有触发/跳过/发布都会记录该身份）。
2. 首页**新建场次**，进入后在「草稿提示」中添加灯光/音效/布景提示，用 ↑↓ 排序，点「前置」勾选依赖。
3. 点**校验依赖**确认无缺失引用与循环依赖，再点**发布执行单**生成不可变版本。
4. 切到「演出记录」，选择版本**启动新演出**，进入执行台：
   - 绿灯 **▶ 触发 GO**（前置全绿才可用）；
   - 红灯 **跳过**（弹窗强制填写原因）；
   - 顶部统计待执行/已触发/已跳过/受阻数量；
   - 全部结束后点「结束本场演出」封存记录。
5. 「已发布版本」中可随时只读回看任意版本快照。

## 本地开发（不使用 Docker）

需要一个可连接的 PostgreSQL 14+。先手动执行 `db/init/01_schema.sql` 初始化库，然后：

```bash
npm install
# 通过标准 PG* 环境变量指向本地数据库，例如：
PGHOST=localhost PGPORT=5432 PGUSER=callboard PGPASSWORD=callboard PGDATABASE=callboard \
  npm start
# http://localhost:3000
```

测试（使用进程内 PostgreSQL，无需安装数据库）：

```bash
npm install
npm test
```

测试覆盖：鉴权、缺失/循环/自引用依赖拦截、发布快照、状态推导（待执行/受阻/触发/跳过）、
前置不满足拒绝触发、跳过必填原因、并发 5 次只记 1 次、草稿改动不影响进行中的演出、历史版本回看等。

## 技术栈与目录结构

- Node.js 20 + Express，关系型数据库 PostgreSQL 16，前端为无构建步骤的原生 HTML/CSS/JS（hash 路由单页）。

```
Dockerfile                # 应用镜像
docker-compose.yml        # app + db 一键编排（含健康检查、数据卷、自动初始化）
.env.example              # 配置样例
db/init/01_schema.sql     # 建表 + 种子数据（首次启动自动执行）
src/app.js                # REST API、静态资源、并发/事务控制
src/db.js                 # 连接池、事务封装（含测试用 pglite 分支）
src/validate.js           # 缺失引用 / 循环依赖校验、现场状态推导
public/                   # 浏览器界面
test/e2e.mjs              # 端到端冒烟测试
```

### 数据模型要点

- `cue_drafts / prereq_drafts`：可自由编辑的草稿与草稿依赖。
- `versions / cues / prereqs`：发布时复制出的**不可变快照**。
- `performances`：演出，外键指向某一版本；`cue_results` 以
  `UNIQUE (performance_id, cue_id)` 保证每个提示至多一条有效结果，
  写入在 `SELECT ... FOR UPDATE` 事务中完成前置判定与冲突告知。

## 安全边界说明

本应用面向本地/内网舞台工作流，操作人身份通过界面选择（请求头 `X-Operator-Id`）以满足留痕需求，
不包含密码鉴权与外网暴露设计。请勿将端口直接暴露到公网。
